# Прошивка

Проект — [`firmware/`](../firmware), PlatformIO, фреймворк Arduino (как в
`DED_CORE_V4`, чтобы переиспользовать провижининг, NVS и OTA-паттерны).

```
firmware/
├── platformio.ini
└── src/
    ├── main.cpp
    ├── config/AppConfig.h        пины, лимиты, профиль платы
    ├── proto/Protocol.h          кадры: типы, сборка/разбор (заголовочный)
    ├── audio/AudioPipeline.*     I2S вход/выход, преролл, VAD, оценка уровня
    ├── net/DeviceConfig.*        NVS: Wi-Fi, ключ устройства, сервер
    ├── net/DeviceIdentity.h      id устройства из MAC (он же на наклейке)
    ├── net/PairingCrypto.*       ключ P-256, расшифровка кадра привязки
    ├── net/BlePairing.*          GATT-сервис привязки и окно видимости
    ├── net/WifiLink.*            подключение к домашней сети, backoff
    ├── net/SpeakerLink.*         WS-клиент, протокол, состояние связи
    ├── app/AudioArbiter.*        кто владеет микрофоном и динамиком
    ├── app/Ui.*                  LED, кнопки, жесты
    └── app/Intents.*             локальные команды и таймеры без сервера
```

## Задачи FreeRTOS

| Задача | Ядро | Приоритет | Стек | Что делает |
|---|---|---|---|---|
| `mic_task` | 1 | 10 | 4096 | I2S DMA → кадр 20 мс → преролл → VAD → очередь вверх |
| `wake_task` | 1 | 8 | 6144 | MFCC + TFLM каждые 20 мс по 0.6 с окну |
| `uplink_task` | 0 | 6 | 4096 | Opus-энкод + отправка кадров `MIC` |
| `downlink_task` | 0 | 7 | 6144 | приём кадров, джиттер, Opus-декод → I2S |
| `link_task` | 0 | 5 | 4096 | Wi-Fi/WS/BLE: состояние, ping, реконнект, привязка, OTA |
| `app_task` | 1 | 3 | 4096 | автомат, LED, кнопки, таймеры, ИК |

Почему именно так: аудио и wake word на одном ядре (метки времени I2S не
пересекаются с сетевыми всплесками), а сеть и декод — на втором. Классический
ESP32 без PSRAM не прощает копирования больших буферов — все передачи через
указатели и фиксированные пулы, ни одного `std::string` в аудиотракте.

## Состояния

```
BOOT → PAIRING (нет Wi-Fi/ключа, окно привязки) ──кадр принят──► перезагрузка → IDLE
IDLE ──wake word / кнопка──► LISTENING
LISTENING ──тишина 400 мс──► THINKING
THINKING ──первый кадр SAY──► SPEAKING
SPEAKING ──SPEECH_END──► IDLE
SPEAKING ──"стоп" / barge_in──► IDLE (поток закрыт)
Любое ──потеря связи──► OFFLINE (локальные умения) ──связь──► IDLE
Любое ──CMD intercom.incoming──► INTERCOM
```

Строка `THINKING` живёт не дольше `MaxDeviceSeconds` (30 с). Дольше — колонка
говорит заранее синтезированной фразой «сервер не отвечает» и уходит в `IDLE`,
а не висит в тишине.

## Тайминги, зашитые в прошивку

| Параметр | Значение | Почему |
|---|---|---|
| кадр I2S | 20 мс | совпадает с Opus-кадром, нет перепаковки |
| преролл | 0.9 с | wake word срабатывает с задержкой — начало фразы не должно потеряться |
| тишина до конца фразы | 400 мс | 900 мс (как в браузере) колонка воспринимает как «тупит» |
| минимальная фраза | 250 мс | короче — это кашель, а не команда |
| джиттер вниз | 3 кадра | 60 мс, дальше слышны провалы |
| ping | 15 с | дешевле, чем ловить зависший TCP по таймауту ответа |
| реконнект | 2 с → ×2 → 60 с | не долбить сервер при массовом отключении питания |

## NVS (namespace `spreaker`)

| Ключ | Тип | Смысл |
|---|---|---|
| `wifi_ssid` / `wifi_pass` | string | сеть |
| `api_base` | string | адрес платформы (`https://api...`) |
| `device_key` | string | ключ из профиля, вводится кодом привязки |
| `name` / `room` | string | «Колонка», «Гостиная» |
| `volume` | u8 | 0–100 |
| `mute` | bool | тумблер + софт |
| `rules_ver` | u32 | версия локальных сценариев |
| `rules` | blob | до 4 КБ — сценарии автономного режима |
| `ir_codes` | blob | обученные ИК-коды |
| `timer_*` | u32 | активные таймеры и будильники |

Ничего, что меняется чаще раза в минуту, в NVS не пишется: у ESP32 флеш
изнашивается, а `Preferences.put*` на каждом кадре убил бы её за месяцы.
Громкость пишется с задержкой 5 с после последнего изменения.

## OTA

Два слота по 1.4 МБ, `otadata` выбирает активный. Обновление — через
`FirmwareService`, тот же путь, что у DED CORE V4:

1. `EVENT {kind:"ota.available", version, url, sha256}` или ручка
   `POST /api/update` при провижининге;
2. скачивание в неактивный слот по HTTPS с проверкой SHA-256;
3. `esp_ota_set_boot_partition` + перезагрузка;
4. если после перезагрузки нет `HELLO_ACK` 3 раза подряд — откат на прежний слот
   (`esp_ota_mark_app_invalid_rollback_and_reboot`).

Ключевое отличие от DED CORE: **нельзя** обновляться, пока идёт разговор.
`link_task` дожидается `IDLE` или прерывает разговор честной фразой.

## Привязка по Bluetooth (единственный способ настройки)

Фронта на устройстве нет. Первый запуск без сети:

1. колонка генерирует пару P-256 и кладёт в NVS (закрытый ключ наружу не уходит
   никогда — наружу идёт только открытый, 65 байт);
2. открывается окно привязки на 5 минут: BLE-реклама с сервисом
   `6b1f0001-…`, имя `DED-SPEAKER-<id>`;
3. сайт читает `info` и передаёт открытый ключ серверу вместе с кодом с
   наклейки; сервер сверяет его с уже закреплённым отпечатком (если он есть),
   выдаёт подписанный grant. Сайт шифрует настройки (ECDH → HKDF → AES-256-GCM)
   кодом кадра, который сообщила колонка: версия 2 — с кодом с наклейки в метке
   HKDF, версия 1 — без него (макет) — и пишет кадр в `pair` кусками по 240 байт;
4. колонка расшифровывает, сохраняет Wi-Fi и одноразовый `pairToken`, гасит BLE
   и перезагружается;
5. `HELLO {token, pub}` → сервер сверяет `pub` с отпечатком привязки, меняет
   токен на долговременный `deviceKey` и закрепляет отпечаток за устройством.

Код привязки в серии лежит в NVS (`spk_id/code`), на макете его можно задать
через `SPEAKER_PAIR_CODE` в `Secrets.h`. С прошитым кодом колонка принимает
только кадр версии 2 и сообщает её полем `frame` в BLE `info`; формула вывода
ключа закреплена векторами в
[`tools/pairing-kdf-check.py`](../tools/pairing-kdf-check.py). Зачем именно так
— [`07-pairing-security.md`](./07-pairing-security.md), серийные требования —
[`09-production-security.md`](./09-production-security.md).

Окно привязки открывается **только по действию человека**: удержание кнопки
5 с. При первом запуске рекламы нет — лента медленно пульсирует синим, пока
человек не нажмёт кнопку. После успеха BLE выключается. Повторная привязка
уже сопряжённой колонки запрещена прошивкой; сначала требуется отвязка
в профиле на сайте. Механика и модель угроз —
[`07-pairing-security.md`](./07-pairing-security.md).

## Микрофон и mute

Выключенный микрофон обязан выключать именно микрофон, а не только ленту:

* `syncMute()` в главном цикле считает состояние из двух источников —
  `deviceConfig.muted` (программный mute) и физического переключателя
  `SW_MUTE`; переключатель читается с подавлением дребезга (три одинаковых
  отсчёта с шагом 20 мс), потому что на профиле DA это GPIO36 без внутренней
  подтяжки и на плате нужен внешний резистор вверх;
* пока mute активен, `audioPipeline.stopCapture()` останавливает захват:
  кадры `MIC` не формируются и на сервер не уходят вовсе;
* переключение отправляется событием `EVENT {kind: muted|unmuted}` и полем
  `muted` в `HELLO`/`STATE`; сервер дополнительно отбрасывает кадры `MIC`,
  пока считает микрофон выключенным — «выключено» не должно зависеть от
  версии прошивки на устройстве;
* лента в этом состоянии красная и перекрывает любое другое состояние.

Стек BLE занимает ~250 КБ флеша и 30–45 КБ RAM. Флеш-бюджет это выдерживает
(прошивка 72 % слота). После привязки BLE-реклама останавливается; полный
выгруз стека пока не реализован.

Выходной тракт выбирается флагом: по умолчанию внешний I2S-ЦАП или I2S-усилитель
(`pio run -e esp32da`), а `pio run -e esp32da_dac` направляет звук во встроенный
8-битный ЦАП ESP32 на GPIO25 — микрофон при этом переезжает на I2S1, потому что
встроенный ЦАП живёт только на I2S0. Стендовая сборка для проверки привязки без
кнопки — `pio run -e esp32da_bench`; в релиз она не входит.

WSS включается только при наличии доверенного CA в локальном
`config/Secrets.h`. Пустой CA — безопасный отказ с сообщением в Serial, без
попытки подключиться с отключённой проверкой сертификата. Без этого файла
устройство не должно отправлять сеть или pairing token на сервер. Для локального
стенда скопируйте `config/Secrets.example.h` в `config/Secrets.h` и замените
placeholder действительным PEM CA сертификатом.

## Локальные умения (`Intents`)

Работают без сервера:

* таймер / будильник / «сколько осталось»;
* громкость, mute, «стоп»;
* ИК-сценарии: «кондиционер 23», «телевизор громче» — коды учатся с пульта и
  хранятся в NVS;
* ESP-NOW: чтение датчиков и подача команд реле;
* локальные правила: «движение в коридоре → включить свет» (порог и действие в NVS).

Распознавание локальных команд — **keyword spotting**, а не STT: 20–30 фраз,
модель на TFLite Micro. Это принципиально: полноценный STT на 520 КБ SRAM без
PSRAM не живёт.

## Что проверяется на устройстве

| Проверка | Как |
|---|---|
| Задержка wake → первый звук | счётчик в прошивке печатает мс в лог |
| Потери кадров | `seq` вниз, раз в 10 с в `STATE` |
| Heap watermark | `esp_get_free_heap_size()` минимум за сессию, в `STATE` |
| Троттлинг | температура кристалла, порог 75 °C |
| Реконнект | выдернуть Wi-Fi роутер на 2 минуты, разговор должен восстановиться |
| Откат OTA | залить заведомо сломанную прошивку в неактивный слот |
| Привязка целиком | Chrome: «Добавить колонку» → код с наклейки → кадр → перезагрузка → `HELLO_ACK` |
| Подмена в эфире | подключиться к колонке телефоном с чужим ключом: `decrypt` должен отказать |
| Язык ленты | каждое состояние видно с 3 м, mute перекрывает любое |
| Крипто-путь | самопроверка на старте: ECDH → HKDF → AES-GCM, `[crypto] ок` |
| Видимость BLE | сканер видит сервис `6b1f0001-…`, `local_name = DED-SPK-<4 hex>` |
| Привязка целиком по BLE | проходит: `stage: paired`, настройки в NVS, перезагрузка |
| Подпись чужим ключом | отвергается: `stage: error, error: grant_signature` |
| WSS без CA | отказ до соединения: `[ws] TLS CA не настроен` |

### Что нашлось только на железе

Три ошибки, каждая из которых ломала привязку целиком и не видна в тестах:

1. **`NimBLECharacteristic::setValue(const char*)` не существует.** Есть только
   `setValue(const uint8_t*, size_t)` и шаблон `setValue<T>(const T&)`, который
   записывает сырые байты типа. Для `const char*` это 4 байта **указателя**:
   характеристика `info` отдавала мусор вместо JSON. Правильно —
   `setValue(reinterpret_cast<const uint8_t*>(s.c_str()), s.length())`.
2. **ArduinoJson с `char*` разбирает на месте.** Документ хранит указатели в
   исходный буфер, поэтому затирание `plain` сразу после разбора превращало все
   строки в пустые — проверка grant падала на «нет полей». Затирание секретов
   перенесено после копирования нужных значений в `String`.
3. **Буферы были малы.** Полезная нагрузка с grant — 638 байт JSON; `plain[512]`
   и `DynamicJsonDocument(384)` её не вмещали. Сейчас `plain[900]`,
   документ 1024, кадр 1024.

### Что нашлось при первом запуске на ESP32-S3

Плата ESP32-S3 DevKitC-1 N16R8 пришла с завода; два дефекта проявились сразу.

**1. Прошивка не загружалась вообще — цикл перезагрузки без сообщений.**

Определение платы `esp32-s3-devkitc-1` в PlatformIO описывает **N8: 8 МБ
флеша и без PSRAM**, а модуль — N16R8. Загрузчик считал флеш
восьмимегабайтным, таблица разделов доходила до 16 МБ, и он молча
перезагружался, не печатая даже баннера. Лечение — объявить возможности
явно:

```ini
board_upload.flash_size = 16MB
board_build.flash_mode = qio
board_build.arduino.memory_type = qio_opi
```

Проверка после сборки: байт 3 в заголовке образа кодирует режим и размер
флеша. Было `0x3F` (8 МБ), стало `0x4F` (16 МБ).

**2. После загрузчика — паника `Double exception` в `applog::begin()`.**

Причина — **повторная инициализация UART0** через `Serial0.begin(115200)` при
включённом `ARDUINO_USB_CDC_ON_BOOT`. Ядро в этом режиме уже поднимает UART0,
и второй `begin()` для того же порта роняет его переполнением стека внутри
`uartBegin`. Точка падения была видна только по символизированной цепочке:
`applog::begin()` рядом с `_xt_alloca_exc`.

Решение: UART0 больше не трогаем, а дублируем логи через ROM-консоль —
она настроена загрузчиком на 115200 и драйвера не требует:

```cpp
esp_rom_printf("%s", chunk);
```

Порциями по 128 байт: у ROM-printf свой буфер, а строки бывают длиннее.

**Заодно нашлась третья мелочь:** буфер `applog::printf` был 256 байт, а JSON
с открытым ключом устройства — около 450. Строка обрезалась ровно посередине
ключа, и сайт не смог бы собрать запрос на привязку. Буфер увеличен до 512.

После исправлений на S3:

```
=== DED CORE SPEAKER 0.1.0 (esp32s3) ===
[boot] устройство 7CE8B1B063DC, свободно 302216 байт
[crypto] самопроверка привязки: ок
[ble] окно привязки открыто: {"id":"7CE8B1B063DC", ... ,"challenge":"..."}
```

Флеш 16 777 216 байт, PSRAM 8 МБ, приложение занимает 1.14 МБ из 3 МБ слота.

Отдельно: **разбор PEM в предсборке mbedtls может быть выключен**, поэтому
открытый ключ подписи закрепляется как несжатая точка P-256 в hex
(`SPEAKER_PAIRING_PUBLIC_KEY_HEX`, 130 символов), а проверка идёт через
`mbedtls_ecdsa_read_signature`. С PEM проверка молча отказывала бы всегда.

## Тракт микрофона: что настроено и почему

Все константы — в `src/config/AppConfig.h`, тракт целиком — в
`src/audio/AudioPipeline.cpp`.

| Что | Значение | Почему так |
|---|---|---|
| Частота | 16 кГц, кадр 20 мс (320 отсчётов) | формат распознавателя; кадр совпадает с шагом отправки |
| Отсечка инфразвука | Баттерворт 4-го порядка, 90 Гц | в комнате гул 40–60 Гц уровня речи; один полюс гасил его лишь на 7 дБ |
| Усиление | ×8 (18 дБ) с мягким ограничителем от 22 000 | речь с двух метров давала −36 dBFS, распознаватель ждёт около −20 |
| Детектор речи | 1300 / 650 по RMS (пороги уже с усилением) | абсолютные пороги без усиления резали фразу на громкие слоги |
| Пауза конца фразы | 600 мс | 400 мс обрывали фразу на естественной паузе |
| Преролл | 900 мс | начало слова не теряется |

Проверка без единого звука: сборка `esp32s3_selftest` подменяет отсчёты
микрофона эталонным тоном 1000 Гц (в динамик он не идёт). Тон приходит на
сервер ровно на 1000 Гц, вспышка 2 с — записью 1.86–2.02 с. Так проверяются
кадры, их темп и разметка частоты, не мешая окружающим.

Обращение к колонке попадает в подсказку распознаванию
(`Assistant:Speaker:WakeWord`, по умолчанию «Колонка»): без него движок
слышит «Колонка, проверка звука» как «Ланка проека звука».

### Обрывы защищённого соединения

Отправка звука идёт не чаще реального времени (один кадр в 20 мс), иначе
преролл выстреливает десятками кадров за один проход `loop()`, mbedTLS не
успевает отправить буфер и отдаёт `-27648` (`SSL - Internal error`), а поток
WebSocket теряет синхронизацию. Если связи нет дольше 30 с, клиент
пересоздаётся, а на второй попытке переподключается Wi-Fi: при «залипшем»
TCP библиотека иначе повторяет SYN до бесконечности.

## Слух при играющей музыке

Колонка слушает комнату, а рядом играет радио из браузера — микрофон слышит те же
колонки компьютера. Эхоподавления на устройстве нет, поэтому договорились так:

* **порог детектора речи адаптивный**: оценка шума поднимается за секунду
  (`delta/64`), поэтому ровный эфир порог не пробивает — колонка ждёт обращение
  поверх музыки, а не шёпот;
* **слух не выключается**: прежний вариант «молчать, пока играет звук» убивал
  возможность услышать кодовое слово;
* **эфир приглушается, а не выключается**: как только колонка начала слушать, она
  сообщает об этом серверу, а сервер — открытой вкладке; вкладка уводит эфир и
  видео до четверти громкости и возвращает звук после конца фразы.

Отдельные правила поверх этого:

| Что | Как ловится |
|---|---|
| Обращение | имя помощника из профиля, сравнение по Левенштейну (1–2 буквы разницы) |
| Голос хозяина | высота тона против эталона из профиля, допуск 0.6 октавы |
| Чих | всплеск 80–360 мс с пиком ≥ 4000, за которым идёт пауза 800 мс |
| Музыка/гул | длинный фрагмент (>9 с) на сервер не уходит вовсе |

## Светодиодная лента

Вспышек нет нигде, кроме входящего звонка: резкий свет в тёмной комнате бьёт по
глазам, а состояние должно читаться боковым зрением.

| Состояние | Лента |
|---|---|
| Ожидание | янтарное перетекание, еле заметное |
| Слушаю | бирюзовая волна, дышит вместе с громкостью |
| Думаю | фиолетовая волна |
| Говорю | зелёная волна по речи |
| Нет сервера | янтарное перетекание с ровным свечением |
| Ошибка | красное плавное дыхание |
| Входящий звонок | стробоскоп |
| Разговор | ровный зелёный |
