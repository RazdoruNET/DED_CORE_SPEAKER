# Этапы и приёмка

## Этап 0 — связь и привязка есть (2–3 дня)

Прошивка собирается, заливается и работает на реальном модуле:

* ключ P-256 создаётся при первом включении и переживает перезагрузку;
* окно привязки по BLE, приём зашифрованного кадра, сохранение сети и токена;
* Wi-Fi STA с откатом, WSS к серверу, `HELLO`/`HELLO_ACK`, `STATE` раз в 10 с;
* лента показывает фазу, кнопка шлёт `EVENT {button}`;
* `CMD {say}` с сервера — колонка подтверждает получение.

**Сделано:** сборка зелёная (RAM 19 %, флеш 72.5 % слота), прошивка залита,
устройство `48AFF3DBF904` поднимается, генерирует ключ и открывает окно привязки.

**Приёмка:** сайт в Chrome привязывает колонку кодом с наклейки без провода;
выдёргивание роутера восстанавливается само; в логе видно `HELLO_ACK`.

## Этап 1 — разговор по кнопке (1–2 недели)

* I2S-микрофон пишет фразу по нажатию, 16 кГц PCM;
* отправка на существующий `POST /api/assistant/voice/transcribe` (ничего нового
  на сервере — быстрый способ проверить весь тракт);
* ответ приходит, синтезируется, колонка играет;
* здесь же замеряется честная сквозная задержка.

**Приёмка:** «Лира, который час» → слышимый ответ. Задержка считается и
печатается; если > 4 с — фиксируем, где теряется.

## Этап 2 — колонка (2–4 недели)

* wake word (MicroWakeWord), преролл, VAD с концом фразы 400 мс;
* Opus вверх/вниз, бинарный WS, джиттер;
* barge-in: «стоп» ловится локально и глушит динамик;
* на сервере — стриминговый STT и склейка с `LiveSpeechStream`.

**Приёмка:**

| Метрика | Цель |
|---|---|
| wake → первый звук (p50) | ≤ 1.5 с |
| wake → первый звук (p95) | ≤ 2.5 с |
| ложные срабатывания за сутки | ≤ 2 |
| пропущенные обращения (тихая комната) | ≤ 1 из 20 |
| потери кадров вниз за 10 мин разговора | ≤ 0.5 % |
| heap минимум за сессию | ≥ 12 КБ |

## Этап 3 — главная док-станция (2–4 недели)

* `SpeakerHomeProvider`: колонка и её датчики в `home.list`;
* `home.set` для громкости, LED, микрофона;
* ИК: обучение с пульта, воспроизведение, `CMD ir.send`;
* ESP-NOW-датчики: приём событий, публикация в `sensor`;
* локальные правила `rules.update` и работа по ним без сервера.

**Приёмка:** «включи кондиционер на 23» работает голосом; датчик двери присылает
событие за ≤ 1 с; при выключенном сервере кондиционер всё равно включается
локальной командой.

## Этап 4 — сессия сайта и интерком (1–2 недели)

* `attach`: список колонок в настройках Лиры, звук браузера уходит в колонку;
* интерком в одну сторону (сайт → колонка), затем полудуплекс.

**Приёмка:** открытая вкладка говорит через колонку, закрытие вкладки отпускает
звук не позже 5 с.

## Этап 5 — продукт (после проверки спроса)

Плата на ESP32-S3 N16R8 + аудиокодек с AEC, корпус, серийная прошивка,
полный дуплекс, медиа.

## Риски

| Риск | Вероятность | Последствие | Что делаем |
|---|---|---|---|
| Нет AEC на классическом ESP32 | факт | эхо при разговоре, полудуплекс | полудуплекс + «стоп» локально; полный дуплекс — только S3 |
| 4 МБ флеша | факт | впритык два слота OTA | `-Os`, без BT, компактный фронт |
| Wake word «Лира» плохо обучается | средняя | плохой детект | MicroWakeWord на синтезе своих же фраз Лиры; при провале — WakeNet на S3 |
| Задержка STT на сервере | высокая | «задумчивая» колонка | стриминговый STT — этап 2, без него этап 3 не начинать |
| Питание/наводки | средняя | Wi-Fi падает на громком звуке | 5 В 2.5 А, звезда земли, 470 µF |
| Эхо собственной музыки в wake word | средняя | ложные срабатывания | развязка микрофонов, порог AFE/KWS, отключение wake на время медиа |
| Приватность (постоянный микрофон) | — | репутационный | аппаратный тумблер питания микрофонов, красная лента при mute, аудио не пишется на сервер |
| Web Bluetooth нет в iOS Safari | факт | привязка с iPhone не работает в браузере | мобильное приложение Capacitor + BLE-плагин; на сайте — «откройте приложение» |
| NVS не шифрован на прототипе | факт | ключ читается по UART | flash encryption + secure boot на серийной плате (обязательный пункт производства) |

## Что делать прямо сейчас

1. Залить скелет прошивки на подключённый модуль, убедиться, что связь с сервером
   и `STATE` работают (этап 0 закрывается одним вечером).
2. Параллельно — стриминговый STT на сервере: он определяет, будет ли продукт
   вообще удобным.
3. Только после этого — паять аудиотракт: пока нет цифры по задержке, нет смысла
   вкладываться в железо.
